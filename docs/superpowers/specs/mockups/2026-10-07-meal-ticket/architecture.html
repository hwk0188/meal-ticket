설계 1/5 · 아키텍처

서버 없이 정적 SPA + Supabase로 구성합니다. 숫자는 교인 폰에서 일어나는 요청 순서입니다.

전체 구조
핵심 결정
  • 앱은 하나. 교인·배식 담당자·권사님이 같은 주소로 들어오고, 로그인한 사람의 역할(member/admin)에 따라 메뉴가 달라집니다. 배식 담당자는 계정이 필요 없습니다(교인 폰을 누르기만 함).
  • 로직은 DB 함수에. 발급·사용·취소·계정 연결은 Postgres 함수 하나가 한 트랜잭션으로 처리합니다. 프론트는 호출만 하므로 잔량이 틀어질 수 없습니다.
  • 권한은 RLS에. 교인은 자기 식권만, 관리자는 전부. 프론트 코드가 공개되어도 데이터는 DB 정책이 지킵니다.
  • 라우팅은 해시 방식. 주소가 …/#/admin 형태라 GitHub Pages의 새로고침 404 문제를 피합니다. 로그인 콜백은 PKCE 방식이라 해시와 충돌하지 않습니다.
  • 운영 자동화는 GitHub Actions. 배포, 3일 간격 ping(일시정지 예방), 주 1회 백업을 모두 무료 한도 안에서 돌립니다. 백업은 개인정보가 있어 비공개 저장소에 둡니다.
  • 홈 화면 설치. PWA 매니페스트를 넣어 "홈 화면에 추가"하면 앱처럼 열립니다. 주일마다 주소를 찾지 않아도 됩니다.
